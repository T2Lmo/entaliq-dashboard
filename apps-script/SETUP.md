# تفعيل: إدارة المكتب، Claude Sonnet للوكلاء، الدخول بـ Google، النشر على LinkedIn و X

الواجهة جاهزة. هذه الميزات لا تعمل حتى تُضبط هذه الخطوات.

## 1) أضف الملفات وعدّل Code.gs (3 تعديلات فقط)
في محرر Apps Script: **+ ← Script** أربع مرات، وانسخ فيها `Auth.gs` و`Social.gs` و`ClaudeBridge.gs` و`Office.gs` كما هي.
ثم في `Code.gs` (ابحث بـ Ctrl+F):

**أ) سطر دالة Gemini** — غيّر الاسم فقط:
```js
function callGemini(systemRole, userPrompt, asJson) {
```
إلى:
```js
function callGeminiApi_(systemRole, userPrompt, asJson) {
```
`ClaudeBridge.gs` يعرّف `callGemini` الجديدة بنفس التوقيع، فكل الوكلاء (نواف، فيصل، لمى، سالم، ريم، زياد، راكان، خالد، سلطان) يمرون عبرها دون أي تغيير آخر.

**ب) داخل doGet** — استبدل:
```js
    authorize_(e && e.parameter && e.parameter.token);
```
بـ:
```js
    const cb = handleSocialCallback_(e); if (cb) return cb;
    authorizeUser_({ token: e && e.parameter && e.parameter.token });
```

**ج) داخل doPost** — استبدل:
```js
    authorize_(data.token);
```
بـ:
```js
    const worker = handleClaudeWorkerAction_(data); if (worker) return worker;
    const user = authorizeUser_(data);
    const social = handleSocialAction_(data, user); if (social) return social;
    const office = handleOfficeAction_(data, user); if (office) return office;
    if (data.action === "claude_status") return json_(Object.assign({ status: "success" }, claudeStatus_()));
```

ثم **Deploy ← Manage deployments ← Edit ← Version: New version** (يبقى رابط /exec نفسه).

## إدارة المكتب (زر 👥 في أعلى اللوحة)
- **الوكلاء:** تعديل تعليمات دور كل وكيل، وتوجيهاتك له، وإيقافه أو تفعيله، وساعات عمله (ساعات المكتب، أو مخصصة، أو دائماً). «استرجاع الأصل» يعيد تعليمات Code.gs.
- **المهام المجدولة:** مهمة لأي وكيل في أيام وساعة محددة (مثال: راكان كل أحد 9:00 يلخّص أخبار الأسبوع). تُنفَّذ إذا كان الوكيل في دوامه، ويدققها سالم، وتظهر في سجل المهام. «تشغيل الآن» للتجربة.
- **التوجيهات والدوام:** توجيهات عامة لكل الوكلاء، وساعات المكتب الافتراضية، وخيار تطبيق الساعات على تكليفاتك اليدوية أيضاً.
- **الأتمتة والهوية:** تكرار رصد الأخبار (كل 1/2/4/6/8/12 ساعة)، ويوم وساعة خطة الأسبوع، ووصف هوية كل علامة الذي تتبعه ريم.
- **تعديل تصميم منشور:** المحتوى ← التصميم ← «تعديل التصميم»: العنوان والسطر الداعم والرقم والنقاط والدعوة ونسخة X.
- **سجل المكتب:** كل إيقاف وتشغيل وتغيير دوام وتكليف وجدولة (ومن نفّذه) يُحفظ في ورقة `OfficeLog` تُنشأ تلقائياً، ويظهر في تبويب «سجل المكتب». هو مرجع راكان (المدير التنفيذي) لمعرفة ما فعله كل وكيل.

## ملخص راكان التنفيذي (Executive.gs)
راكان هو المدير التنفيذي: يعرف ما فعله كل وكيل ويلخّص نتائجهم.
- **الملخص:** بطاقة راكان ← «الملخص». يقرأ المهام وتدقيق سالم والأخبار والمحتوى وسجل المكتب للفترة (يوم/أسبوع/شهر)، ويكتب: الخلاصة، أبرز النتائج، ما يحتاج انتباهك، ما أنجزه كل وكيل، ومقترحات تكليف تعتمدها بزر «كلّف» أو «جدولة».
- **الأرقام** (عدد المهام، متوسط تقدير سالم، أقل من 70%، غير المكتملة…) يحسبها الخادم من السجلات مباشرة؛ راكان يكتب القراءة فقط.
- **المواعيد:** إدارة المكتب ← الأتمتة والهوية ← «ملخص راكان التنفيذي»: يومي (الافتراضي 16:00) وأسبوعي (الافتراضي الخميس 14:00). يعمل فقط وراكان في دوامه، ويُتخطى إن لم يكن للفريق نشاط. **بعد لصق الملف اضغط «حفظ وتحديث المشغلات» مرة واحدة** لإنشاء مشغلات الملخص.
- يُحفظ كل ملخص في ورقة `Reports` تُنشأ تلقائياً.
- **عند تكليف راكان مباشرة** يُضاف لمهمته «مرجع الفريق» (آخر 7 أيام: مهام كل وكيل وتقديراته وآخر ملخص)، ويراه سالم عند التدقيق. سجل المهام يحفظ نص مهمتك الأصلي فقط.

**إن كنت تستخدم ملفات منفصلة:** أضف `Executive.gs` كملف جديد، وفي `doPost` داخل Code.gs استبدل سطر تنفيذ التكليف:
```js
    const agentOutput = callGemini(AGENTS_PROMPTS[agentName], taskText);
```
بـ:
```js
    const agentInput = typeof execTaskContext_ === "function" ? execTaskContext_(agentName, taskText) : taskText;
    const agentOutput = callGemini(AGENTS_PROMPTS[agentName], agentInput);
```
وفي سطر `runAudit_` الذي يليه غيّر `task: taskText` إلى `task: agentInput`. إجراءات `exec_*` تمر عبر `handleOfficeAction_` فلا يلزم تعديل آخر.

## استوديو المحتوى (Studio.gs): الوكلاء ينفذون وأنت تعتمد أو ترفض
- **كل ساعة** (الافتراضي، منشوران في الدورة): لمى تكتب كل فكرة لم تُكتب ويدققها سالم، ثم ريم تصمم وزياد يكتب نسخة X. يصلك المنشور في «للمراجعة» جاهزاً: **اعتمد أو ارفض** (أو اطلب إعادة الكتابة بملاحظة، وتُحفظ ملاحظتك في العقل).
- يعمل فقط ولمى وسالم وريم وزياد في دوامهم. ما يتعثر مرتين (مثل خبر بلا مصدر محفوظ) يبقى لك لتكمله يدوياً.
- **الأسلوب:** لمى وزياد يكتبان نصوصاً إبداعية للسوق السعودي (خطاف من الحياة اليومية، مواسم سعودية، تنويع القوالب، رؤية 2030 حين تنطبق، بلا أرقام غير موثقة).
- **الهوية:** ريم تصمم دائماً بإحدى هويتي المكتب فقط: **انطلق** أو **وهج**، ولا تخلط بينهما ولا تبتكر ثالثة. منتجا أثر وساعد يُصممان بهوية انطلق (في الملف الكامل عُدّلت `brandOf_` لذلك؛ في الملفات المنفصلة احذف سطر `return "أثر"` منها).
- الإعدادات في «الأتمتة والهوية»، وزر **«أكمل المنشورات الآن»** في نافذة المحتوى.

## مازن: مرسل بريد محترف لاستقطاب العملاء (Prospects.gs)
- **كل يوم 20 منشأة** (الإعداد الافتراضي): فنادق ومستشفيات ومولات ومجمعات سكنية وشركات سعودية تناسب وهج وانطلق. يعمل كل ساعة في دوامه، حتى 5 منشآت في الدورة، ويتوقف عن البحث عند بلوغ هدف اليوم.
- **مطلع على الفريق:** يقرأ أخبار نواف آخر 3 أسابيع وقراءة فيصل لكل خبر (المستجدات، الاتفاقيات، شركات الطاقة، فرص الترشيد) وآخر ملخص لراكان؛ يستخدمها لاختيار المنشآت وكخطاف في الرسالة، ويراها سالم عند التدقيق.
- **البريد:** فقط المنشور في موقع المنشأة الرسمي مع رابط الصفحة، ويتحقق الخادم أنه مكتوب فيها. ما لم يتحقق، أو بدا شخصياً، أو من نطاق مختلف، أو قدّره سالم أقل من 70%، يظهر في «تحقق يدوي».
- **الرسائل:** بنية مرسل بريد محترف (افتتاحية مخصصة، قيمة واحدة، دعوة واحدة، توقيعك، وسطر عدم المراسلة)، نص عادي بلا تنسيق. سالم يدقق الدفعة كاملة في استدعاء واحد.
- **لا يُرسل شيء قبل موافقتك:** بطاقة مازن ← «الفرص» ← «للموافقة»: حدد الرسائل واضغط «أرسل المحدد». تدخل «الطابور» متباعدة (الافتراضي 3 دقائق) في أيام وساعات الإرسال (الأحد–الخميس 09:00–16:00) وبحد يومي (40). يمكنك إلغاء أي رسالة قبل موعدها.
- **المتابعة:** بعد 5 أيام بلا رد يكتب مازن متابعة قصيرة في نفس المحادثة («رد: …») بقيمة جديدة من مستجدات السوق، وتنتظر موافقتك في «للموافقة». عدد المتابعات قابل للتعديل (0–2). **اضغط «ردّوا» حين تصلك إجابة** حتى لا تُكتب متابعة لمن رد.
- **إن انقطع العامل أثناء إرسال رسالة** لا تُعاد تلقائياً (حتى لا تصل مرتين)؛ تظهر في «تعذر الإرسال» لتتحقق من صندوق المرسل ثم تعيد المحاولة.
- يُحفظ كل شيء في ورقة `Prospects` (تُرقّى أعمدتها تلقائياً)، وكل دفعة مسودات أو متابعات سطر واحد في سجل المهام باسم مازن. عند «ردّوا» تُقترح الرسالة مثالاً لمازن في العقل.

### الإرسال من بريد الشركة (Hostinger) عبر العامل على جهازك
1. في `worker/.env` أضف (كلمة المرور تبقى على جهازك فقط ولا تصل للخادم):
   ```
   SMTP_HOST=smtp.hostinger.com
   SMTP_PORT=465
   SMTP_USER=info@entaliq.com.sa
   SMTP_PASS=كلمة مرور صندوق البريد
   MAIL_FROM=info@entaliq.com.sa
   MAIL_FROM_NAME=انطلق للطاقة
   MAIL_BCC=info@entaliq.com.sa
   ```
   `MAIL_BCC` اختياري: نسخة مخفية من كل رسالة إلى بريدك لتجدها عندك.
2. شغّل `worker/start-worker.cmd`: يثبّت مكتبة البريد مرة واحدة (`npm install`)، ثم يرسل ما حان موعده.
3. للتجربة: `node claude-worker.mjs --mail-test` داخل مجلد worker يرسل رسالة تجريبية إلى بريدك.
4. في اللوحة يظهر «البريد: يرسل من …» حين يتصل العامل. إن كان مطفأً تنتظر الرسائل في الطابور حتى يعود.

### قراءة الوارد: الردود توقف المتابعات تلقائياً
- **تعمل تلقائياً** مع بيانات SMTP في `worker/.env` (نفس البريد وكلمة المرور، وخادم `imap.hostinger.com`)، أو بقيم `IMAP_*` منفصلة. للتجربة: `node claude-worker.mjs --inbox-test`.
- **الخصوصية:** يقرأ العامل صندوق الوارد كل 5 دقائق، ويفتح ويرسل للخادم **فقط** ما يخص رسائل مازن: ردٌّ في نفس المحادثة، أو من بريد أو نطاق منشأة راسلناها، أو إشعار ارتداد يذكر بريدها. بقية بريد الشركة لا يُفتح ولا يغادر جهازك. لا يُطابَق بالنطاق البريد العام مثل gmail.
- **التصنيف** (قواعد سريعة ثم مازن لما يحتاج قراءة): مهتم، يطلب معلومات، ليس الآن، غير مهتم، إلغاء المراسلة، تحويل، رد آلي، ارتداد.
  - مهتم / يطلب معلومات / ليس الآن / تحويل ← «ردّوا»: تتوقف المتابعات وتُلغى أي متابعة في الطابور. الرد المهتم يُقترح مثالاً لمازن في العقل.
  - غير مهتم / إلغاء المراسلة ← «مستبعد»، ولا يقترحها مازن مجدداً.
  - ارتداد ← «تعذر الإرسال» والبريد «مرتد»؛ صحّحه أو استبعد المنشأة.
  - رد آلي (خارج المكتب) ← ملاحظة فقط، والمتابعة مستمرة.
- يظهر الرد على بطاقة المنشأة (النوع، المرسل، الملخص، النص)، ومعدل الرد يحسب الردود البشرية فقط، وراكان يرى ردود الفترة في ملخصه.
- المكتبات: `start-worker.cmd` يثبّت مكتبتي قراءة البريد تلقائياً عند أول تشغيل بعد التحديث (`npm install`).

نصيحة لسمعة البريد: تأكد من ضبط SPF و DKIM و DMARC لنطاق الشركة في Hostinger (لوحة البريد ← إعدادات DNS) قبل الإرسال اليومي.

**إن كنت تستخدم ملفات منفصلة:** أضف `Studio.gs` و`Prospects.gs` بعد Code.gs (يضيف Prospects.gs مازن إلى `AGENTS_PROMPTS`). وفي `doPost` بعد سطر `const worker = handleClaudeWorkerAction_(data); if (worker) return worker;` أضف:
```js
    const mailer = typeof handleMailWorkerAction_ === "function" ? handleMailWorkerAction_(data) : null; if (mailer) return mailer;
```

## بدر: المنافسات والمناقصات (Tenders.gs)
- **الرصد اليومي** (الافتراضي الساعة 10، 5 فرص و3 ترسيات): يتنقل بين الطاقة الشمسية وصيانتها، كفاءة الطاقة وتدقيقها، التكييف والتبريد، إدارة المباني والعدادات، الإنارة الموفرة. المصادر: صفحات المنافسات في مواقع الجهات، إعلانات ترشيد وشركة شراء الطاقة والمركز السعودي لكفاءة الطاقة، وطلبات عروض الشركات والمجموعات الكبرى. يحتاج عامل Claude.
- **منصة اعتماد محمية من القراءة الآلية**؛ لا يحاول بدر تجاوز ذلك. انسخ أي منافسة تراها في اعتماد والصقها في «أضف منافسة» ليحللها.
- **الحكم من لوحة الجاهزية:** «تقدّم مباشرة»، «بعد التسجيل في اعتماد» (منافسة حكومية بلا حساب مورد)، «كمقاول باطن أو شريك» (تحتاج تصنيفاً وليس لديكم، أو ترسية)، «تجاهل» (ملاءمة ضعيفة أو انتهى الموعد). التصنيف يُعتبر مطلوباً للأعمال والصيانة الحكومية بعقد 500 ألف ريال فأكثر. يُعاد الحكم تلقائياً كلما حدّثت الجاهزية.
- **الترسيات:** «حوّلها لمازن» ينشئ منشأة عند مازن بقطاع «مقاولون فائزون»، فيكتب لها رسالة شراكة كمقاول باطن (لا عرض وفر)، وبريد الفائز يُتحقق منه من صفحته.
- **«اطلب من سلطان المستندات والعرض»** يفتح تكليف سلطان بتفاصيل المنافسة: المستندات المطلوبة وما ينقص، هيكل العرض الفني، وأسئلة قبل موعد الاستفسارات.
- **الجاهزية:** حساب مورد في اعتماد، التسجيل لدى أرامكو والجهات الكبرى، التأهل لدى ترشيد، رخصة تدقيق الطاقة، تصنيف المقاولين، وتواريخ انتهاء مستندات الشركة. المستندات التي تنتهي خلال 30 يوماً والمواعيد القريبة تظهر في ملخص راكان.
- يُحفظ كل شيء في ورقة `Tenders`، وإعدادات الجاهزية في Script Properties. المؤشران في اللوحة: «ملاءمة الفرص المفتوحة» و«جاهزية المناقصات».
- بعد لصق الملف اضغط «حفظ وتحديث المشغلات» لإنشاء مشغل الرصد اليومي.

**إن كنت تستخدم ملفات منفصلة:** أضف `Tenders.gs` بعد Code.gs (يضيف بدر إلى `AGENTS_PROMPTS`). الإجراءات `tenders_*` تمر عبر `handleOfficeAction_`.

## عقود صيانة وتشغيل الطاقة الشمسية (Contracts.gs)
- **المدخل:** بطاقة سلطان ← «العقود»، أو من مازن «اعمل عرض صيانة شمسية» لمنشأة ردّت (تُملأ بياناتها تلقائياً).
- **الأسعار والباقات أولاً:** ثلاث باقات افتراضية (الأساسية، القياسية، الشاملة) بعدد زيارات التنظيف والفحص والمراقبة والتقارير وأوقات الاستجابة، قابلة للتعديل. **السعر تضعه أنت**: ريال لكل كيلوواط ذروة سنوياً مع حد أدنى. لا يُصدر عرض لباقة بلا سعر، والوكلاء لا يقترحون أسعاراً.
- **الحساب:** القيمة السنوية = القدرة × السعر (ولا تقل عن الحد الأدنى)، وقيمة المدة بحسب عدد الأشهر، وضريبة القيمة المضافة 15% (قابلة للتعديل). جدول الزيارات يوزَّع بالتساوي على المدة وتُدمج الزيارات في اليوم نفسه.
- **النص:** بنود العقد قالب ثابت (الموضوع، النطاق، مستوى الخدمة، الالتزامات، الاستثناءات، المقابل المالي، المدة والتجديد، الإنهاء، المسؤولية، السرية، النظام الواجب التطبيق). **يُنصح بمراجعته مع مستشار قانوني مرة واحدة قبل اعتماده.** سلطان يكتب خطاب التقديم والملاحظات الفنية الخاصة بالموقع فقط، ويدققها سالم.
- **الطباعة:** «عرض السعر» (خطاب، بيانات المنظومة، مقارنة الباقات بسعرها لهذه المنظومة، القيمة، الصلاحية) و«العقد» (البنود، جدول الزيارات، القيمة، التوقيعات) يُطبعان أو يُحفظان PDF من المتصفح.
- **السجل:** عرض مسودة ← أُرسل العرض ← «قبل العميل: فعّل العقد» (بتاريخ البداية الفعلي فيُعاد الجدول) ← الزيارات («تمت» مع ملاحظة) ← «جدّد» قبل الانتهاء. الزيارات المتأخرة والتي خلال 7 أيام والتجديدات خلال 60 يوماً تظهر في ملخص راكان.
- **مازن:** قطاع جديد «منشآت لديها ألواح شمسية»: يبحث عن منشآت ركّبت ألواحاً ويعرض عليها عقد الصيانة دون أسعار. فعّله من إعدادات مازن إن كانت قطاعاتك محفوظة من قبل.
- يُحفظ كل شيء في ورقة `SolarContracts`، والأسعار في Script Properties.

**إن كنت تستخدم ملفات منفصلة:** أضف `Contracts.gs`. الإجراءات `contracts_*` تمر عبر `handleOfficeAction_`.

## ملخص الصباح من راكان وتنبيه توقف العامل (Digest.gs)
- **ما يصلك كل صباح** (الافتراضي 8:00، الأحد–الخميس):
  - ما ينتظر موافقتك: رسائل مازن ومتابعاته، والمنشورات، ودروس العقل، وعروض الصيانة.
  - ردود العملاء منذ أمس.
  - مواعيد اليوم: زيارات الصيانة والتجديدات، والمنافسات التي تنتهي خلال 7 أيام، والمستندات التي تقترب من الانتهاء.
  - حالة الفريق وآخر خلاصة لراكان، مع زر يفتح اللوحة.
  
  الأرقام تُقرأ من السجلات مباشرة، دون نموذج.
- **تنبيه العامل:** يفحص الخادم كل ساعة. إذا لم يتصل العامل على جهازك منذ 30 دقيقة، في أيام الملخص وضمن النافذة (الافتراضي 08:00–18:00)، يصلك بريد واحد عن هذا الانقطاع، ويتكرر بعد 24 ساعة إن استمر. لا يصل تنبيه إن لم يُشغَّل العامل أصلاً.
- **الإرسال:** من خادم المكتب عبر بريد Google (`MailApp`) من حساب Google الذي يشغّل الخادم، فيصلك حتى لو كان جهازك مطفأً. الحصة المجانية 100 رسالة يومياً، وتكفي.
- **التفعيل (مرة واحدة):**
  1. حدّث كود الخادم واحفظه، ثم **Deploy ← Manage deployments ← Edit ← Version: New version**.
  2. في المحرر اختر الدالة `digestAuthorize` من القائمة، واضغط **Run**، ووافق على إذن إرسال البريد.
  3. في اللوحة: إدارة المكتب ← الأتمتة والهوية ← «ملخص الصباح من راكان». اكتب البريد المستلم (أو اتركه فارغاً ليصل إلى بريد حساب Google)، ثم اضغط «حفظ وتحديث المشغلات».
  4. «معاينة» تعرض محتوى اليوم دون إرسال، و«أرسل ملخص اليوم الآن» للتجربة.
- الحالة محفوظة في Script Properties (`DIGEST_STATE` و`WATCHDOG_STATE`)، وكل إرسال وتنبيه يُسجَّل في «سجل المكتب».

**إن كنت تستخدم ملفات منفصلة:** أضف `Digest.gs`. الإجراءات `digest_*` تمر عبر `handleOfficeAction_`.

## راكان بالصوت (Voice.gs)
- **المدخل:** زر الميكروفون العائم فوق زر المساعد (يفتح «راكان بالصوت» ويبدأ الاستماع)، أو خانة الكتابة في اللوحة نفسها.
- **الصوت في المتصفح:** يحوّل المتصفح كلامك إلى نص بالعربية السعودية، ويصل النص فقط إلى الخادم. يعمل في Chrome أو Edge أو Safari، ويحتاج إنترنت وإذن الميكروفون أول مرة.
  - الرد يُنطق بصوت عربي مثبت على الجهاز، مثل «Microsoft Naayf» في Windows. Edge فيه أصوات سعودية طبيعية.
  - تختار الصوت والسرعة من «إعدادات الصوت»، أو تجعل الردود مكتوبة فقط.
- **الأسئلة (رد فوري من السجلات، بلا نموذج):**
  - وش ينتظرني اليوم، والموافقات، وكم رد جانا.
  - هل العامل شغال، ومين موقوف أو يداوم.
  - وش سوى أي وكيل اليوم، والمنافسات، وزيارات الصيانة.
- **الأوامر:**
  - «أوقف خالد»، و«خل خالد يداوم»، و«أوقف خالد وشغّل ريم». إيقاف كل الوكلاء يطلب تأكيدك أولاً.
  - «مازن جهّز شركات اليوم»، و«بدر دوّر منافسات»، و«كمّل المنشورات»، و«اكتب ملخص الأسبوع». تُشغَّل بإجراءاتها المعتادة، ويقرأ راكان النتيجة عند انتهائها.
  - «أرسل ملخص اليوم على إيميلي».
- **التكليف بالصوت:** أي طلب عمل بكلامك، مثل «لمى اكتبي منشور عن ترشيد التكييف» أو «جهّز عرض تدقيق طاقة لفندق».
  - **من ينفذه:** الوكيل الذي ذكرته. وإن لم تذكر أحداً، فمن يناسب نوع العمل: منشور لمى، تصميم ريم، تغريدة زياد، عرض أو عقد سلطان، رسالة تعريفية مازن، منافسة بدر، تحليل سوق فيصل، خبر نواف، مراجعة سالم، برمجة خالد، خطة أو رأي راكان. وراكان لأي طلب آخر أو سؤال لا تجيبه السجلات.
  - **قبل التنفيذ:** يقرأ عليك راكان ما فهمه ومن سينفذه. تقول «أكّد» أو «إلغاء»، أو «لا، خله لسلطان» لتحويله، أو تضغط «عدّل قبل الإرسال» لتصحح النص في «تكليف وكيل».
  - **التنفيذ:** بالتكليف المباشر المعتاد عبر العامل على جهازك، ويدققه سالم ويُحفظ في سجل المهام. يأخذ عادة من نصف دقيقة إلى دقيقتين.
  - **بعد الانتهاء:** يقرأ عليك راكان خلاصته (أول جملتين أو ثلاث) وتقدير سالم، والنص كاملاً في المحادثة مع زر نسخ. وإن أغلقت اللوحة يصلك تنبيه على الشاشة مع الصوت، وزر الميكروفون ينبض ما دام الوكيل يعمل.
  - **حدود:** تكليف واحد في كل مرة، وتقدر تسأل في الأثناء. الباحث يدوي، فطلبه يُجهَّز في «تكليف وكيل».
- **الموافقات بالصوت:** قل «خلنا نراجع اللي ينتظرني»، أو «وافق على رسائل مازن»، أو «اعتمد المنشورات»، أو «راجع الدروس».
  - **ما يُعرض:** رسائل مازن ببريد موثّق ومتابعاته، والمنشورات المسودة، والدروس المقترحة للعقل. حتى 20 رسالة و10 منشورات و10 دروس في المرة.
  - **ما لا يُعرض أبداً:** الرسائل التي تحتاج تحققك من البريد، والتي تعذر إرسالها. يذكر راكان عددها، وتبقى من صفحة مازن.
  - **لكل بند:** يقرأ راكان لمن هو، وموضوعه، وتقدير سالم، والنص يظهر في اللوحة. تقول:
    - «أرسل» أو «اعتمد».
    - «ارفض» مع السبب (مثل «ارفض لأنه طويل»)، أو يسألك عن السبب. سبب رفض المنشور يُحفظ في عقل لمى.
    - «تخطّ» أو «لا»، أو «اسمع النص» ليقرأه كاملاً، أو «وقف» لإنهاء المراجعة.
  - **التنفيذ:** بإجراءات الصفحات نفسها. الرسالة تدخل طابور الإرسال المتباعد، ويقول لك أول موعد، وتقدر تلغيها من الطابور في صفحة مازن قبل موعدها. وإن كان العامل متوقفاً، ينبهك أن الرسائل تنتظر حتى يشتغل.
  - **حماية:** إن تغيّر منشور من صفحته أثناء المراجعة، يتخطاه ولا يعتمد نسخة قديمة.
  - في النهاية يلخص لك ما أرسلت واعتمدت ورفضت وتخطيت.
- **ما لا يتم بالصوت:** الحذف، والنشر على LinkedIn وX (من صفحة المحتوى بعد الاعتماد).
- كل أمر نُفِّذ بالصوت يُسجَّل في «سجل المكتب» بعلامة «بالصوت». لا إعدادات في الخادم: يكفي تحديث الكود ونشر نسخة جديدة.

**إن كنت تستخدم ملفات منفصلة:** أضف `Voice.gs` بعد `Digest.gs`. الإجراء `voice_ask` يمر عبر `handleOfficeAction_`.

## مسار المبيعات (Pipeline.gs)
- **المدخل:** زر القمع في أعلى اللوحة، أو بطاقة سلطان ← «المبيعات»، أو اسأل راكان: «وش الصفقات اللي تنتظرني؟».
- **المراحل واحتمالها:** مهتم 10% ← اجتماع 25% ← زيارة ودراسة 40% ← عرض مرسل 60% ← تفاوض 80% ← ربحنا أو خسرنا. «المتوقع» = مجموع القيمة × الاحتمال للصفقات المفتوحة.
- **الصفقات تنضاف وحدها** (بلا تكرار، كلما فتحت المسار):
  - **من مازن:** كل رد «مهتم» أو «يطلب معلومات»، باسم المنشأة وبريدها وملخص ردها، وخطوة قادمة لليوم: «رد على اهتمامهم واقترح اجتماعاً».
  - **من بدر:** المنافسة «نجهز العرض» بقيمتها وموعد تقديمها، وتتبع حالتها: قُدّم ← عرض مرسل، وفزنا ← ربحنا، ولم نفز ← خسرنا.
  - **من عروض الصيانة الشمسية:** العرض الجديد يصير صفقة بقيمته طوال مدة العقد. والعرض المعمول لمنشأة ردّت على مازن يُربط بصفقتها: أُرسل العرض ← عرض مرسل، وساري ← ربحنا، ومرفوض ← خسرنا.
  - **قاعدة المزامنة:** تقدّم المرحلة فقط ولا ترجعها، ولا تمس صفقة أغلقتها بنفسك، ولا تغيّر خطوة كتبتها أنت.
- **بيدك:** «+ صفقة» لما يأتيك من غيرها (اتصال، معرض، الموقع)، وتحريك المرحلة، و«حدد الخطوة القادمة» وموعدها (اليوم، بكرة، بعد أسبوع)، و«ربحنا» بالقيمة النهائية، و«خسرنا» مع السبب، وإعادة فتح صفقة مغلقة.
- **من الصفقة نفسها:** «اطلب عرضاً من سلطان» يجهز له التكليف ببيانات الصفقة، و«عرض صيانة شمسية» يفتح عرضاً جديداً بالاسم والمدينة.
- **الأرقام:** المفتوحة وقيمتها، والمتوقع، وربح الشهر، ونسبة الفوز في 90 يوماً، والخطوات التي حان موعدها والمتأخرة. وتنبيه للصفقة التي بلا حركة 14 يوماً، وللصفقة التي بلا قيمة.
- **يصل لك:** خطوات اليوم والمتأخرة في ملخص الصباح، وخلاصة المسار في ملخص راكان التنفيذي ومرجع مهامه.
- كل صفقة في ورقة `Deals` تُنشأ تلقائياً. كل حركة في سجل الصفقة وفي «سجل المكتب».

**إن كنت تستخدم ملفات منفصلة:** أضف `Pipeline.gs`. الإجراءات `pipeline_*` تمر عبر `handleOfficeAction_`.

## التقاط العملاء من الموقع (Leads.gs)
- **النموذج:** صفحة «اطلب تواصلاً» (`lead.html`) بهوية انطلق أو وهج، تعمل على الجوال. فيها: الاسم، والمنشأة، والجوال أو البريد، والمدينة، والخدمة، والرسالة، وموافقة الزائر على التواصل معه.
- **التركيب (مرة واحدة):**
  1. حدّث كود الخادم وانشر نسخة جديدة. يجب أن يبقى النشر **Who has access: Anyone** كما هو الآن، لأن الزائر يرسل الطلب بلا تسجيل دخول.
  2. في اللوحة: مسار المبيعات ← «من الموقع» ← «النموذج وإعداداته». اضغط «حفظ وتحديث المشغلات» مرة.
  3. انسخ «كود التضمين» لكل علامة، والصقه في صفحة «تواصل معنا» بموقعها. أو اربط زر «اطلب عرضاً» بـ«الرابط». وشارك الرابط في واتساب وإنستغرام ورمز QR.
  4. جرّبه بنفسك من الموقع، وتأكد أن الطلب ظهر في «من الموقع» ووصلك بريد التنبيه.
- **مع كل طلب سليم، فوراً:**
  - يُحفظ في ورقة `Leads`.
  - تنشأ صفقة «مهتم» في مسار المبيعات، وخطوتها «اتصل بهم» لليوم.
  - يصلك بريد تنبيه فيه بيانات العميل ورابط واتساب.
- **إن ترك بريده:** يكتب مازن رداً قصيراً خلال 10 دقائق. هو رد على طلبه، لا رسالة تسويقية. يدققه سالم، ثم يصلك في «تنتظر موافقتك» عند مازن، أو بالصوت: «وافق على رسائل مازن». لا يُرسل شيء إلا بموافقتك، والخادم لا يراسل الزائر من نفسه أبداً.
- **في اللوحة لكل طلب:** «اتصل»، و«واتساب» بتحية جاهزة تعدّلها قبل الإرسال، و«بريد»، و«راجع رد مازن»، و«تواصلنا»، و«مزعج»، و«افتح الصفقة».
- **الحماية من الإزعاج:**
  - رمز النموذج: «غيّر رمز النموذج» يوقف الروابط القديمة فوراً، فتنسخ الجديدة إلى الموقعين.
  - حقل فخ مخفي، وزمن تعبئة أدنى (3 ثوانٍ).
  - حد للطلبات: 6 في الدقيقة، و40 في اليوم (قابل للتعديل).
  - دمج المكرر: نفس الجوال أو البريد خلال 24 ساعة يُدمج في الطلب الأول.
  - المشتبه (روابط كثيرة) يُعلَّم بلا صفقة ولا تنبيه، وتقدر تدخله المسار بـ«حقيقي».
  - الصفحة لا ترسل إلا إلى رابط Google Apps Script.
- **أين يظهر:** طلبات الموقع منذ أمس في ملخص الصباح، و«كم عميل جانا من الموقع؟» بالصوت، و«نموذج الموقع» في صحة المكتب.

**إن كنت تستخدم ملفات منفصلة:** أضف `Leads.gs`. وفي `doPost` داخل Code.gs، أضف هذا السطر قبل `const user = authorizeUser_(data);` مباشرة، لأن الطلب يصل بلا تسجيل دخول:
```js
    const lead = typeof handleLeadPublic_ === "function" ? handleLeadPublic_(data) : null; if (lead) return lead;
```
الإجراءات `leads_*` للوحة تمر عبر `handleOfficeAction_` كالمعتاد.

## صحة المكتب (Health.gs)
- **المدخل:** إدارة المكتب ← «صحة المكتب»، أو اسأل راكان بالصوت: «هل المكتب سليم؟». تظهر نقطة حمراء أو صفراء على زر إدارة المكتب إن وُجدت مشكلة. يُفحص بهدوء بعد فتح اللوحة، ثم كل 30 دقيقة.
- **ما يفحصه:**
  - **الخادم:** نسخته مقارنة باللوحة، ووجود كل وحداته، ورمز الدخول، ومحرك الذكاء (Claude مع WORKER_TOKEN أو Gemini بمفتاحه)، وإذن Google للبريد وحصته اليومية، والمشغلات الآلية مقارنة بإعدادات الأتمتة (الناقص والمكرر والزائد).
  - **العامل على جهازك:** آخر اتصال، والطلبات المنتظرة، وإرسال بريد مازن، والرسائل التي تعذر إرسالها مع آخر سبب، وقراءة الوارد.
  - **الوكلاء:** أخطاء آخر 7 أيام، والموقوفون، ومن متوسط تقدير سالم له أقل من 70%. وجدول لكل وكيل فيه تكليفاته وتقديره وآخر تكليف.
  - **الأتمتة والنشر والبيانات:** آخر ملخص صباحي، وآخر ملخص تنفيذي، وربط LinkedIn وX وموعد انتهائه، وحجم الجدول مقارنة بحد Google Sheets.
  - **هذا المتصفح:** هل يدعم الميكروفون، وهل فيه صوت عربي.
- **الإصلاح:** كل خلل معه طريقة إصلاحه. «أعد تثبيت المشغلات» يصلح المشغلات بضغطة، والباقي يفتح لك الصفحة المعنية. الفحص لا يرسل شيئاً ولا يغيّر شيئاً.
- **بعد تحديث الخادم:** إذا ظهرت مشكلة «نسخة الخادم»، فالكود المنشور قديم. الصق الكود الكامل وانشر نسخة جديدة. وإذا توقفت اللوحة كلها برسالة Authorization، شغّل `digestAuthorize` في المحرر مرة ووافق.

**إن كنت تستخدم ملفات منفصلة:** أضف `Health.gs`. الإجراءات `health_*` تمر عبر `handleOfficeAction_`.

## عقل المكتب ومرجعه (Brain.gs)
دروس وقواعد وأمثلة يقرؤها كل وكيل قبل كل مهمة ليتحسن مع الوقت. تُحفظ في ورقة `Brain` تُنشأ تلقائياً.
- **ما يُستخدم:** المعتمد فقط. قبل كل استدعاء يُضاف للوكيل «مرجع الخبرة»: دروسه ودروس «الكل» (حتى 10 دروس، نحو 1800 حرف)، وأحدث مثال معتمد من عمله للأسلوب فقط دون نقل أرقامه.
- **مصادر التعلم:**
  - ملاحظتك عند **رفض منشور** أو **طلب إعادة كتابته** تُحفظ «ملاحظة المدير» معتمدة للمى.
  - سجل المهام ← **«علّم الوكيل»** (درس معتمد لهذا الوكيل أو للجميع) و**«احفظه مثالاً»** للمخرجات 85% فأكثر.
  - **مراجعة راكان الأسبوعية** (الافتراضي الخميس 15:00): يقرأ تدقيقات سالم الأقل من 75% وملاحظاتك في آخر 14 يوماً ويقترح دروساً عامة، ويقترح أعلى مخرج لكل وكيل (90%+) مثالاً. **المقترحات لا تُستخدم حتى تعتمدها.**
- **الإدارة:** إدارة المكتب ← «العقل والمرجع»: اعتماد، تعديل، إيقاف، رفض (يبقى ليتجنب راكان اقتراحه مجدداً)، حذف، وإضافة درس يدوياً، و«راكان: اقترح دروساً الآن».
- **الأثر:** لكل وكيل متوسط تقدير سالم في آخر 14 يوماً مقابل الـ14 يوماً التي قبلها.
- موعد المراجعة في «الأتمتة والهوية»؛ اضغط «حفظ وتحديث المشغلات» بعد لصق الملف لإنشاء مشغلها.

**إن كنت تستخدم ملفات منفصلة:** أضف `Brain.gs` كملف جديد. لا يلزم تعديل Code.gs: الحقن يتم في `officeSystemFor_` وإجراءات `brain_*` تمر عبر `handleOfficeAction_`.

## أدوات الوكيل تحت اسمه (في اللوحة الرئيسية)
تحت كل بطاقة وكيل: حالته (في الدوام / خارج الدوام / موقوف) وساعاته، وثلاثة أزرار:
- **الدوام:** ساعات المكتب أو مخصصة أو دائماً (إجراء `office_set_hours`، لا يمس تعليماته وتوجيهاته).
- **إيقاف / تشغيل:** يوقف كل أعماله اليدوية والمجدولة والآلية أو يعيدها.
- **تكليف:** «نفّذ الآن» (نفس مسار تكليف وكيل مع تدقيق سالم) أو «مهمة مجدولة متكررة» بأيام وساعة.

تظهر الأدوات فقط إذا كان الخادم يحتوي Office.gs؛ مع الخادم القديم تبقى البطاقات كما كانت.

**إن كنت تستخدم ملفات منفصلة بدل الملف الكامل:** أضف في `doPost` داخل Code.gs بعد سطر حفظ التكليف في Tasks (`ss.getSheetByName("Tasks").appendRow([taskId, …`):
```js
    if (typeof officeLog_ === "function") officeLog_("تكليف مباشر", agentName, taskId + " — " + taskText.slice(0, 200), officeBy_(user));
```

بعد التركيب افتح «الأتمتة والهوية» واضغط **حفظ وتحديث المشغلات** مرة واحدة: يستبدل مشغلات installNewsTrigger بمشغلات تحترم ساعات العمل، ويضيف مشغل المهام المجدولة.
الرصد الآلي يعمل فقط إذا كان نواف وفيصل ولمى وسالم في دوامهم، وخطة الأسبوع إذا كان راكان ولمى وسالم في دوامهم.

هذه التعديلات آمنة قبل ضبط أي مفاتيح جديدة: بدون `AI_ENGINE=claude` يبقى Gemini كما هو، والرمز `ACCESS_TOKEN` الحالي يبقى يعمل.

## الوكلاء بـ Claude Sonnet (بدون API)
الخادم يضع طلب الوكيل في طابور، و**عامل على جهازك** ينفذه بـ Claude Code باشتراكك ويعيد الرد.
التعليمات المرسلة لـ Claude هي نفسها التي كانت تُرسل لـ Gemini: دور الوكيل + القواعد العامة + ملف الشركة من ورقة Company.

1. Script Properties: `WORKER_TOKEN` = رمز عشوائي طويل (غير ACCESS_TOKEN).
2. على جهازك: انسخ `worker/.env.example` إلى `worker/.env` واملأ `EXEC_URL` (رابط /exec) و`WORKER_TOKEN`.
3. شغّل `worker/start-worker.cmd` واتركه مفتوحاً.
4. Script Properties: `AI_ENGINE` = `claude`. (لإرجاع Gemini: احذفها أو غيّر قيمتها.)
5. اختياري: `CLAUDE_FALLBACK` = `gemini` ليُستخدم Gemini تلقائياً إذا كان جهازك مطفأ (مفيد لرصد الأخبار كل 6 ساعات وخطة السبت 9 صباحاً). و`CLAUDE_MODEL` (الافتراضي `sonnet`).

اختبار سريع للعامل بدون الخادم: `node worker/claude-worker.mjs --once "سؤال"`

ملاحظات:
- الوكلاء يعملون فقط وجهازك شغّال والعامل مفتوح (أو مع `CLAUDE_FALLBACK=gemini`).
- كل طلب يُحسب من حدود اشتراكك في Claude. رصد الأخبار يستدعي حتى 4 وكلاء لكل خبر، وتكليف وكيل = وكيل + تدقيق سالم.
- الانتظار محكوم بميزانية التنفيذ الحالية في Code.gs؛ ما لا يكتمل (مثل بقية خطة الأسبوع) يُستكمل في الدورة التالية كما كان.
- الباحث يبقى على وضع النقل اليدوي (`RESEARCH_MANUAL_MODE`) ولا يتغير.
- **التشغيل التلقائي مع Windows:** شغّل `worker/install-autostart.cmd` مرة واحدة. يبدأ العامل مصغّراً كل مرة تدخل فيها Windows. للإلغاء: `worker/remove-autostart.cmd`.
- **إعادة التشغيل الذاتي:** إذا توقف العامل لأي سبب، يعيد `start-worker.cmd` تشغيله بعد دقيقة. ولا يشتغل منه إلا نسخة واحدة: لو فتحته مرتين، تُغلق الثانية وحدها.
- إذا نام الجهاز يتوقف العامل معه. اضبط النوم من إعدادات Windows ← النظام ← الطاقة إن أردت أن يبقى المكتب شغالاً في ساعات العمل.

## 2) الدخول ببريدك (Google)
1. افتح Google Cloud Console ← APIs & Services ← Credentials ← Create credentials ← **OAuth client ID** ← Web application.
2. في **Authorized JavaScript origins** أضف: `https://t2lmo.github.io`
3. انسخ الـ Client ID وضعه في:
   - `js/config.js` ← `const GOOGLE_CLIENT_ID = "…";`
   - Script Properties ← `GOOGLE_CLIENT_ID`
4. Script Properties ← `ALLOWED_EMAILS` = بريدك (وأي بريد آخر، مفصول بفواصل).
5. بعد التأكد أن الدخول يعمل: `ALLOW_SHARED_TOKEN` = `false` لإيقاف الرمز المشترك.

## 3) LinkedIn
1. developer.linkedin.com ← Create app (اربطه بصفحة الشركة).
2. Products: **Sign In with LinkedIn using OpenID Connect** و **Share on LinkedIn**.
   للنشر باسم صفحة الشركة: اطلب **Community Management API** (يحتاج موافقة LinkedIn) وضع `LINKEDIN_ORG_URN` = `urn:li:organization:<رقم الصفحة>`.
3. Auth ← Authorized redirect URLs: رابط `/exec` بالضبط.
4. Script Properties: `LINKEDIN_CLIENT_ID`, `LINKEDIN_CLIENT_SECRET`.
5. صلاحية الربط 60 يوماً؛ تظهر في الإعدادات، ثم أعد الربط.

## 4) X
1. developer.x.com ← Project ← App ← User authentication settings:
   OAuth 2.0، النوع **Web App (confidential client)**، الصلاحيات Read and write.
2. Callback URI: رابط `/exec` بالضبط. Website: `https://t2lmo.github.io/entaliq-dashboard/`
3. Script Properties: `X_CLIENT_ID`, `X_CLIENT_SECRET`.
4. راجع باقة X API الحالية وسعرها: النشر عبر الـ API له حدود حسب الباقة.

## 5) الاستخدام
الإعدادات ← «حسابات النشر المباشر» ← ربط. في المنشورات المعتمدة يظهر «انشر الآن على LinkedIn / X»، مع تأكيد قبل النشر، وصورة تصميم ريم تُرفق تلقائياً. الخادم يتحقق بنفسه أن المنشور معتمد ولم يتغير، ويمنع نشره مرتين على الشبكة نفسها.
